# Optional self-service developer trial

Status: **not performed**. No participants have been recruited or contacted. Controlled accounts, agent-authored acceptance tasks and passing tests are not independent usability, comprehension or ROI evidence. The owner cannot currently arrange external developers; this protocol is ready for voluntary future use and does not block accurately describing the technical build.

The current technical exercise is an authored invoice-import HTTP app. Its intentional regression truncates a validated customer ID during invoice lookup. It is not a claimed upstream vulnerability or private customer incident. The exact engine and task freeze, first six results, three repeated-profile successes and safe negative outcomes are available alongside this file.

Run a future trial with three to five consenting support escalation engineers, maintainers or developers. A participant can follow the public guide independently and return the table below; no screen recording or customer data is required. Use only owned or expressly authorised inputs and application code. Keep originals and credentials out of returned results. Outreach requires separate authorisation.

1. Record role, relevant experience, runtime and task familiarity. Use a participant code rather than a name/email in the shared record.
2. Start from the installation/profile instructions in a clean environment. Count active and elapsed setup time, including adapter preparation, dependency installation, errors and author help.
3. Use an unfamiliar supported failing input. Compare ordinary manual fixture preparation with ReproShare. Alternate task order between participants; disclose order and prior exposure. Include unsuccessful or refused attempts.
4. Reuse the same profile for three different supported inputs without code edits. Record every profile/adapter change separately.
5. A second participant with application-code access receives only the reviewed synthetic package and public instructions. They should run the actual assertion without the original customer input or private source issue.
6. After a 30-second product explanation, ask the participant to explain why changed data can retain the failure, who retains the original, and what information is still visible. Record their answer before explaining it again.

Proposed goals are 10–15 minutes for a first engineer connection and under two minutes for a repeated supported handoff. These are **unmeasured targets**. Do not claim time savings, comprehension rates, adoption or willingness to pay until observed. Report a three-person study as a three-person study and preserve unsuccessful rows.
